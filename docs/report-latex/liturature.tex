\textbf{Benchmarks and metrics.} Spider \cite{yu2018spider} is the standard cross-domain benchmark; BIRD \cite{li2023can} moves to large real-world databases with dirty values, and Spider-Realistic \cite{deng2020structuregrounded}, Spider-Syn \cite{gan2021towards} and Spider-DK \cite{gan2021exploring} probe robustness to wording, synonyms and domain knowledge. Execution Accuracy has replaced exact string match as the preferred metric, because equivalent queries can differ in form.

\textbf{Approaches.} Graph-based encoders such as RAT-SQL \cite{wang2019ratsql} and LGESQL \cite{cao2021lgesql}, table pre-training \cite{yin2020tabert, yu2020grappa} and constrained decoding \cite{scholak2021picard} gave way to methods built on large language models \cite{liu2023a, pourreza2023dinsql, gao2023texttosql, wang2023macsql, talaei2024chess, pourreza2024chasesql}. CodeS \cite{li2024codes}, reproduced here, instead builds open models by incrementally pre-training StarCoder \cite{li2023starcoder}. Its reported Spider development-set results are 77.9\% Execution Accuracy for CodeS-1B, 83.4\% for 3B, 85.4\% for 7B and 84.9\% for 15B.

\section{Research gap}

\begin{itemize}
	\item \textbf{No reported confidence.} The reviewed systems answer every question with the same apparent confidence; none reports an accuracy--coverage trade-off or declines to answer.
	\item \textbf{Closed models.} Most of the strongest systems send the schema to a hosted model, which raises cost, privacy and reproducibility concerns.
	\item \textbf{The benchmark-to-reality gap.} Results are reported on Spider, whose questions often name the columns and whose databases are small; how a Spider-trained model behaves on realistic wording and real-world databases is rarely measured for the same system.
\end{itemize}

This project uses the candidates CodeS already produces to measure agreement, abstains when agreement is low, evaluates the result as an accuracy--coverage trade-off with significance tests, and measures the same system beyond Spider.
